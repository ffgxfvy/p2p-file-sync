# 线协议说明

## 分层

```
传输层：TCP（可靠字节流）
消息层：JSON Lines —— 一条消息一行，以 \n 结束
数据层：裸字节 —— 长度由消息里的 size 字段给定
```

选择 JSON Lines 而不是二进制打包的理由：

- **可调试**：用 `nc 127.0.0.1 8888` 手打一行 JSON 就能查询对端清单；
- **中文/空格安全**：JSON 负责转义，只要字段值里不含裸换行即可；
- **可扩展**：加字段不需要改帧格式。

文件内容用裸字节紧跟消息尾发送，避免 base64 的 33% 膨胀，也不需要自己实现二进制分帧。

## 消息类型

| 类型 | 方向 | 字段 | 说明 |
|---|---|---|---|
| `HELLO` | 广播 | `node_id`, `tcp_port` | 节点周期性广播自己（默认 3 秒一次） |
| `LIST` | C → S | — | 请求文件清单 |
| `MANIFEST` | S → C | `files: {name: {name,size,mtime,sha256}}` | 清单应答 |
| `GET` | C → S | `name`, `offset` | 请求文件；`offset > 0` 表示断点续传 |
| `FILE` | S → C | `name`, `size`, `sha256`, `offset` | 文件应答头，**其后紧跟 `size - offset` 字节裸数据** |
| `DONE` | S → C | `name`, `size`, `sha256` | 该文件发送完毕 |
| `ERROR` | S → C | `message` | 出错应答 |

## 时序

### 拉取清单

```
C                                    S
│  {"type":"LIST"}                    │
├────────────────────────────────────►│
│                                     │  扫描共享目录，计算 SHA-256（带缓存）
│  {"type":"MANIFEST","files":{...}}  │
│◄────────────────────────────────────┤
```

### 下载（含续传）

```
C                                          S
│  {"type":"GET","name":"a","offset":N}    │
├──────────────────────────────────────────►│
│                                          │  校验文件名；offset 越界则归零
│  {"type":"FILE","size":T,"sha256":H,"offset":N}
│◄──────────────────────────────────────────┤
│  ◄──── 裸字节：T − N 字节 ────►           │
│  {"type":"DONE",...}                     │
│◄──────────────────────────────────────────┤
│                                          │
├─ 本地计算全量 SHA-256，与 H 比对          │
├─ 通过 → .part 改名为正式文件              │
└─ 失败 → 删除 .part 并抛 ChecksumError     │
```

**偏移越界保护**：若客户端留下的 `.part` 比远端的完整文件还大（例如远端文件变小了），
服务端会把 `offset` 归零，并在应答里如实告知；客户端看到 `header["offset"] != 请求的 offset`
时会删除本地残留并从 0 重新接收——否则内容会错位。

## 边界与防护

| 情况 | 处理 |
|---|---|
| 控制消息不是合法 JSON | `ProtocolError` |
| 控制消息缺少 `type` 字段 | `ProtocolError` |
| 单条控制消息 > 1 MiB | `ProtocolError`（防恶意超长行） |
| 数据流提前关闭 | `ProtocolError`（期望字节数 vs 实际收到数） |
| 文件名含 `/`、`\`、`..` 或为绝对路径 | `FileNotFoundError`（服务端拒绝） |
| 收到的内容哈希不匹配 | `ChecksumError`，删除 `.part` |
| 目标文件已存在 | 默认生成 `a (1).txt`；`overwrite=True` 时覆盖 |

## TCP 连接的复用方式

每条控制消息一次"读一行 → 读 N 字节（如有）→ 写一行 → flush"的严格交替，
因此不存在粘包歧义，也不需要在协议里额外加长度前缀或分隔符。

服务端在一个连接上循环处理多条消息（`LIST` 之后可以紧接着 `GET`），
由客户端决定何时关闭。
